# Admin & Support System Implementation

## Overview
This PR implements a comprehensive **Role-Based Access Control (RBAC)** system with dedicated admin and support modules for user management and customer service operations.

## What's New

### 🔐 Role-Based Access Control (RBAC)
- **Three-tier role hierarchy**: `ADMIN` > `SUPPORT` > `USER`
- **Database-driven roles**: Roles stored in database (single source of truth)
- **Account suspension**: Admins can suspend/unsuspend user accounts
- **Global authorization**: `RolesGuard` enforces role-based access across all endpoints

### 👨‍💼 Admin Module (`/api/v1/admin`)
8 new endpoints for system administration:
- `GET /users` - List users with pagination and filters
- `GET /users/:id` - View detailed user information
- `POST /users/:id/suspend` - Suspend user account
- `POST /users/:id/unsuspend` - Restore suspended account
- `PATCH /users/:id/role` - Change user role
- `DELETE /users/:id` - Delete user (with safeguards)
- `GET /stats` - System statistics and metrics
- `GET /audit-logs` - Search audit logs

**Security Features**:
- ✅ Cannot suspend/delete yourself
- ✅ Cannot suspend/delete other admins
- ✅ Suspended users blocked at JWT validation level
- ✅ All admin actions automatically logged

### 🎫 Support Module (`/api/v1/support/tickets`)
6 new endpoints for customer support:
- `POST /tickets` - Create support ticket (all users)
- `GET /tickets` - List tickets (role-filtered visibility)
- `GET /tickets/:id` - View ticket details
- `PATCH /tickets/:id` - Update ticket (support/admin only)
- `POST /tickets/:id/messages` - Add message with threading
- `POST /tickets/:id/close` - Close ticket

**Features**:
- Auto-incrementing ticket numbers
- Internal staff notes (hidden from users)
- Automatic status transitions based on responder
- Priority levels: LOW, MEDIUM, HIGH, URGENT
- Categories: TECHNICAL_ISSUE, ACCOUNT_ISSUE, BILLING, FEATURE_REQUEST, etc.
- Full audit trail via `TicketActivity` model

## Technical Decisions

### Single Source of Truth
- `Role` enum generated by Prisma from database schema
- Re-exported via `src/common/enums/role.enum.ts` with helper functions
- All modules import from centralized location

### Type-Safe Queries
- Changed Prisma queries from `include` to `select` for explicit field typing
- Ensures TypeScript recognizes all model fields (role, suspension, etc.)

### Security-First Design
- Suspension check at JWT validation level (blocks all API access)
- Role-based ticket visibility (users see only their own)
- Multiple safeguards prevent dangerous operations
- Comprehensive audit logging via interceptor
